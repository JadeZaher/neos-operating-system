# Node support

`NodeAdmin` is an explicit assignment to a global `User`, independent of organization roles and editable profiles. Assignment, account disable and every support command serialize on the protected `node_admin_support_lock` row. Revocation and disabling cannot remove the last usable administrator. A usable account is enabled and has a sign-in method or a live authentication session.

Schema migration never grants authority from legacy builder/co-creator profiles. On an unbootstrapped database, the server accepts a reviewed comma-separated `NODE_ADMIN_BOOTSTRAP_USER_IDS` list. It validates all accounts before assigning any, writes public server-bootstrap events, then seals `node_admin_bootstrap_complete`. Empty configuration assigns nobody and seals nothing. Configuration is deployment input; no user identifiers are hardcoded in source. Organization founders and ordinary profile updates never gain node authority.

`node_admin_catalog.py` declares every supported ORM resource. New models fail the inventory test until deliberately classified. Each state family supports typed corrections; human evidence supports administrative archival and restoration of the exact original records. Authentication records expose safe metadata and revocation, never secret values. Audit, assignments and private archives are protected internal tables, managed through dedicated operations.

An evidence archive includes permitted dependent evidence rows, ordered for FK-safe removal/restoration; conflicting non-evidence references stop the operation. Restoration cannot overwrite an existing original row or substitute new human statements. Alignment-event archival/restoration adjusts its recorded member score delta. Public events identify an administrative correction and affected row count; immutable private snapshots retain original bodies and before/after values. Do not expose snapshot bodies through public audit or ordinary profile/chat serializers.

Support commands use the real user actor, explicit organization scope and validated references. Creating an organization proposal stores user-level support provenance and leaves `proposer_member_id` empty. Agreement corrections snapshot the prior version and regenerate its fingerprint. Ordinary organization policy predicates remain unchanged. Support state corrections intentionally bypass workflow gates and do not fabricate member consent, co-signatures or independent human approval.

Existing-row commands require the inspected content digest as `expected_version`. Commands and their public event/private snapshot commit atomically. Inspection/listing events commit before their payload returns. API/tool boundaries persist redacted failure outcomes after the failed transaction rolls back. Audit unavailability fails closed; private SQL errors and payloads must not escape to chat logs.

The public reason is a category: **Technical support**, **Account recovery**, **Organization support**, **Agent testing**, **Data correction**, **Access management**, or **Service recovery**. Catalog publishes `reason_categories`; UI must offer these as a selector. Legacy free text normalizes to Technical support and is never copied into public records. Public changes report field names and opaque IDs, without private bodies, private organization names, credentials or arbitrary request text.

`require_admin` compatibility endpoints write an immutable attempt before access and a correlated completion outcome, with allowlisted resource category, UUID target and field names. New support commands provide atomic change/event behavior. `is_platform_admin` is a compatibility alias of explicit node assignment; it is no longer derived from a home-ecosystem profile.

Public GET-only `/node-admin/roster` identifies active enabled operators with their user UUID, public display name, profile URL and computed Node admin badge. `/node-admin/audit` and individual audit events are public GET-only. Grant/revoke roster, account search, resources, archives and commands require a current explicit node administrator. Earned badge awards cannot create node authority.
